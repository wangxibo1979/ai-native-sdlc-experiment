## 具体发现及证据

1. **样本枚举冗余。** 规格 L3 定义完整正数 long 域、无额外业务上限；L5 定义首次请求的两个结果。T26–T33 将 1、2147483648L、Long.MAX_VALUE - 1、Long.MAX_VALUE 分别展开为返回值和操作次数，重复 T05/T06；T34–T38 又展开上界重放及冲突。R02–R08 保留完整值域，删除重复行不等于放弃边界；具体取样属于后续检查方式，有限样本本身不能证明全域。
2. **次数与历史重复。** T07/T09、T08/T10 分别是重放一次与多次；T44/T45 是成功重试后的同一 L6 规则。统一为 R04/R05，明确“每次”且包括成功重试后的提交。T46/T47 保留为 R18/R19，因为 L9 特别规定故障开关开启时的已提交相同重放，这个例外条件不能遗漏。
3. **冲突范围原来偏窄。** T11–T13 和 T36–T38 只写不同正数金额。L7 原文为 different amount，并未限定正数，L8 又明确非正金额非法。已提交键改为 0 或负数仍须 IAE，旧回执及计数保持不能无依据只覆盖正数冲突。R06–R08 恢复为任意不同 long 金额；R11/R12 独立保留一般非正数拒绝规则。
4. **原审计 Q3 不能变成异常类别自由选择。** L7 指定同键异金额 IAE，L8 指定非法输入 IAE，均未给故障开启的豁免。不能接受“开故障时所有调用一律先抛 ISE”来绕过这些规则。R06/R09/R11 明确保留类别，但不规定内部校验顺序。同时两字段非法时均为 IAE，先报哪个字段及错误消息未知。若将 L9 的 new request 扩至非法输入，则与 L8 字面要求冲突，应修订规格而非把两种结果都验收通过。
5. **原审计 Q8 混合了策略未知与结果确定。** 自动重试、退避、次数上限和时限未知；但故障持续开启且键仍未提交时，下一次合法尝试仍符合 L9 新请求故障条件。不能因“只举一次失败”而允许下一次忽略开关。R13 保留重复适用，R17/R05 分别规定成功一次和后续重放不再操作；没有新增自动重试策略。
6. **T41 不应删去或虚报覆盖。** L9 明确故障前不提交回执。R15 保留此语义，但不要求新增查询接口。仅“失败后重试返回非 null”不足以单独证明失败期间无已提交回执；证据可得性尚待后续确认。
7. **键和唯一性实例可归并。** T02/T03 是大小写及外围空格样本，T04 是内容同而实例不同的 String；R01 表达统一的精确内容等价关系。T48/T49 是 L10 同金额/异金额的唯一性实例，R20 保留“不依赖金额是否相同”的完整量词；键等价关系和不同键回执唯一性仍是两个独立目标。

## 未决问题及边界

- Q1：blank 的完整字符定义是什么，是否采用 Java 17 String.isBlank？空串和纯 ASCII 空格确定非法，制表、换行及 Unicode 字符的完整归类未指定算法。不得静默规定 NBSP、零宽字符的类别，也不能以两个样本代替整个 blank 域。R09/R10 保留原要求。此缺口影响完整键域验收。
- Q2：API、类名、故障传入方式、计数读取方式和回执查询能力是什么？仅给语义，没有接口契约。计数以相对变化表达，不发明初值 0。R15 的证据可得性尚未核实。
- Q3：错误消息、同时多字段非法时先报告哪个字段未知；IAE 类别已确认。若要求 new request 包括非法请求，需解决与 L8 的文本冲突；当前不能把开关作为豁免输入或冲突规则的许可。
- Q4：真实金额单位、币种、精度、累计余额、实际支付审批是什么？未知且不得静默加入。缺口阻止将合成模型通过解释为真实支付可用性，不改变正数 long 接受域。
- Q5：ID 类型、格式、排序、空字符串许可、跨 ledger 或跨进程唯一性是什么？仅确认非 null、重放稳定和同 ledger 不同合法键唯一，不指定 UUID 或全局保证。
- Q6：非法输入或失败后的内部日志、回执候选分配、未提交内部状态还有哪些约束？未全面定义。仅明定故障无提交回执、冲突旧回执保持及各自计数约束；不发明其他内部状态门槛。
- Q7：自动重试、退避、最多次数和时限是什么？策略未知不使每次调用的确定结果变成可任选。
- Q8：long 之外数值、文本金额解析和转换怎么处理？规格无此输入契约，不增加解析层目标。
- 明确排除：分布式、持久化、崩溃、并发等能力不作为本轮待实现功能。
